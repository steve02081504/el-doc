# 文件预处理

文件预处理在普通词法分析和源码宏展开之前改写源文本。下表及后文描述语言合同；示例仅作静态语法核对，不表示已由当前编译器编译或运行。

## 指令速查

指令占一条物理行：行首可有空格或制表符，随后是 `#` 和完整指令名，名字后必须是空白或行尾。

| 写法 | 作用 |
| --- | --- |
| `#define NAME replacement` | 记录文本替换；替换体可为空，重复定义覆盖旧值 |
| `#undefine NAME` | 删除定义；名字未定义时无操作 |
| `#include "source"` | 在当前位置包含单个来源的文本 |
| `#include sources("first", "second")` | 按参数顺序包含零个或多个来源 |
| `#include directory("./fragments")` | 按成员名字的确定顺序包含目录的直接文件成员 |
| `#if condition` | 开始条件分支 |
| `#else_if condition` | 在此前分支未命中时选择后续分支 |
| `#end_if` | 结束当前文件中的条件组 |
| `#error "message"` | 发出错误并终止预处理 |
| `#warning "message"` | 保存带位置的警告，继续处理 |

没有 `#else`；剩余分支写 `#else_if true`。不提供函数式 define、`##`、C 字符串化或反斜杠跨行续接。未知 `#name` 留给原生或扩展词法；表达式中的私有成员访问不是预处理指令。替换结果不会再次识别为指令。

## 文本替换与作用域

名字按完整名称字符片段匹配，区分大小写；不会在较长名字或数字名称片段中替换子串。替换不理解 EL 的绑定、类型或表达式，也不自动处理转义和引号。活动普通行中的字符串、DSL 和保留的注释文字同样参与替换。

以下是独立的局部示意，展示替换文本而非程序输出：

```el
#define COLOR blue
let description = "COLOR" // 字符串内容替换为 blue
let COLORFUL = 1           // 较长名字保持不变
```

替换体在引用时按当时的宏环境递归展开，定义时不提前展开；后续重新定义或删除会影响后续引用。直接或间接展开环会报诊断并列出展开链。预定义项不能重新定义或删除。

普通模块导入、默认 prelude 和其他模块的语法接口分别从只含预定义项的新环境开始。宏环境在当前模块预处理结束时销毁，不导出给其他模块，也不延续到之后的编译请求。

## 条件语法

条件读取器不运行 EL，不调用用户函数、getter、源码宏或 I/O。

| 形式 | 含义与限制 |
| --- | --- |
| 十进制整数、正负号 | 零为假，其余为真 |
| `true`、`false` | `t`、`nil` 分别等价 |
| `defined('NAME')` | 检查定义；也接受双引号或未加引号的单个名字 |
| `time('2026-11-01')` | 返回该日 UTC 午夜的精确 Unix 秒常量 |
| `== != < <= > >=` | 比较，不支持连锁比较 |
| `!`、`&`、`|`、括号 | 优先级从高到低为括号／前缀、比较、`&`、`|` |

不支持算术、一般函数调用或 `&&`、`||`。普通宏先在条件中机械展开，`defined` 和 `time` 的操作数字面内容不展开。活动条件中的未知裸名字会报诊断，不按零处理；布尔组合的所有操作数都检查语法。

`time` 还接受 `YYYY-MM-DDTHH:MM:SS[.fraction](Z|±HH:MM)`：完整日期时间必须有显式偏移，小数秒最多九位。年份范围为 0001–9999；拒绝闰秒、`-00:00`、转义和尾随字符。它不读取当前时间或环境时区。

以下为独立的条件选择片段：

```el
#define VERSION 7
#if defined('VERSION') & VERSION >= 7 & VERSION < 9
let selectedVersion = VERSION
#else_if true
let selectedVersion = 0
#end_if
```

未选区域只维护条件嵌套和文件闭合，不展开宏、不读取或枚举 include、不发现 import，也不触发 error/warning。分支已经命中后，后续 `else_if` 条件不求值。未选的普通文本不必是合法 EL，但注释边界及条件结构仍受检查；include 不能跨文件关闭条件。

## include 与模块导入

`#include` 是文本包含，使用当前文件的同一宏环境；其中的定义和删除影响后续包含内容及返回后的当前文件。它不创建模块、初始化器或独立声明身份，声明仍属于宿主模块。普通 `import` 创建模块边界，导入者的 define 不改变被导入模块实例。

include 参数经机械替换后必须是来源字符串、`sources(...)` 或 `directory(...)`，不执行一般表达式。字符串可用单引号、双引号或无插值的反引号形式，按 EL 字符串规则解码转义。集合拒绝尾随表达式、目录内的子目录、缺失能力和重复名字。

来源与普通 import 共用项目映射、provider、获取能力和错误路径，不额外取得权限。`./`、`../` 相对引用以写下指令的实际输入位置及 provider 为基准；无协议的其他名字必须经项目映射。指定文件不会试探后缀或退回本地同名文件；单来源指向目录时使用模块目录的 `index.el`，目录集合则需要 provider 支持枚举等能力。`http:`／`https:` 的合同不代表当前环境的网络路径已经运行验证。

活动 include 环会被拒绝，没有 C include guard 例外。目录成员和读取内容都是构建输入；无法确认来源快照仍有效时不得复用缓存。

## 注释、诊断与来源

预处理识别指令时感知注释、字符串、模板、自定义原文字面量和 import 正则边界，避免把受保护位置中的 `#` 当作指令。真正指令参数中的注释视为空白，普通行的注释字符保留给正常词法处理；这一识别保护不禁止普通行中的机械替换。

error/warning 消息必须是字符串字面量，不接受裸文本或拼接表达式；反引号消息可以使用模板转义，但不能执行未转义的 `${...}`。指令正文不保留为可执行语句，换行和来源映射保留。

展开后的 token 始终引用同一份展开文本；独立来源映射保留原始位置、include 链和 define 定义链。替换的主诊断指向引用点并附定义点；包含文本的诊断指向其输入来源。诊断位置不会改变模块归属或宿主模块的资源绑定。

默认界限为展开、include 和条件表达式嵌套深度 128，一次模块替换次数 1,000,000，展开 Unicode 标量数 67,108,864；越界会明确诊断，不静默截断。

## 预定义来源值

| 名字 | 替换内容 |
| --- | --- |
| `__BUILTIN_FILEPATH__` | 当前引用点源 URI 的带引号、正确转义的 EL 字符串字面量 |
| `__BUILTIN_LINENUMBER__` | 当前引用点从 1 开始的物理行号；include 使用包含文件位置 |
| `__BUILTIN_LINE_CONTENT__` | 引用点所在物理行的预处理前原文，转换为带引号、正确转义的 EL 字符串字面量；不含行尾 |
| `__BUILTIN_FILE_CONTENT__` | 引用点所在输入文件的完整预处理前文本，转换为带引号、正确转义的 EL 字符串字面量 |
| `__EVIL_EDITION__` | 当前编译器产物构建时间的 Unix 整数秒，同一 image 内固定 |

旧拼写 `LINENUMER` 不提供别名。上述值同样机械替换，不能假设放进字符串后会智能去掉引号。`__EVIL_EDITION__` 不是语言年份版本，也不是编译用户程序时的当前时间。

两个内容项都读取已经取得的源文本快照，不重新读取文件。行内容保留缩进、注释和原始宏名；文件内容还保留预处理指令、未选分支、原始 LF／CRLF／CR 行尾及可选 BOM，不把 include 替换成被包含的内容。第一行的行内容也保留 BOM。

在 include 内引用时，内容来自被包含文件；通过 define 间接引用时，内容来自本次引用点，而非 define 定义点。生成字面量中的宏名不会再次展开。这两项同样不能被 define 或 undefine。

以下是预处理结果对照，不是程序输出：

```el
let sourceLine = __BUILTIN_LINE_CONTENT__
```

进入普通词法分析的文本为：

```el
let sourceLine = "let sourceLine = __BUILTIN_LINE_CONTENT__"
```

`__BUILTIN_FUNCTION_INFO__` 则是保留的原生表达式，文件预处理原样保留它；字符串内只是普通文字。它在函数内产生包含 `name`、`kind`、`module`、`file`、`line`、`column` 的位置快照，模块顶层拒绝使用；它不是完整运行期反射或函数身份。

## eval 文本的预处理

按语言合同，`eval` 的输入也必须先经过本预处理阶段，再进入普通词法与编译流程。每次求值从只含预定义项的新宏环境开始，不继承调用者或先前求值的 define。

根求值文本的 FILEPATH 项固定生成字符串字面量 `"your lovely mom"`，行号从该文本第一物理行的 1 开始。行内容与文件内容分别读取本次求值文本的原始行和完整原文。这个展示地址不授予来源获取能力，也不充当相对路径基址或模块身份；include 仍使用显式来源能力，被包含文件中的来源值取其真实来源信息。

!!! note "实现状态"
    标准库 eval 与持久求值会话尚无完整实现；这里说明其预处理合同，不表示当前已有可调用的 eval API。

## 与源码宏的区别

预处理处理文本，没有 EL 名称绑定、导入重命名或类型语义。源码宏在后续语法阶段按声明身份参与展开，仍受名字、类型、效果和生命周期规则约束。要组织模块使用 import；要操作语法与绑定使用源码宏；只有需要条件文本选择或文本包含时才使用预处理。
