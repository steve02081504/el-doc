# 复制消除

把新对象交给变量或函数时，EL 不要求为了每经过一层就再制造一个副本。复制消除减少中间对象，同时保留程序需要的独立值和资源清理。

| 情形 | 规则 |
| --- | --- |
| 同一具体类型的新构造结果或已拥有右值，直接初始化绑定、按值形参或返回结果 | 必须直接交付，不为中间运输额外复制 |
| 拥有临时值经隐式复制继续交付 | 可以合并复制链；被省略的临时复制及其副作用可以消失 |
| 已存在、仍可独立修改的具名值 | 必须保持值隔离，不能为了省复制让它们意外成为同一对象 |
| 普通复制函数的显式调用 | 不自动纳入临时隐式复制链的省略规则 |
| 类型转换或实际要求的移动构造 | 仍按所选转换和移动合同处理，不能借复制消除绕过 |

## 直接交付是什么意思

以下是语义片段，`Point` 使用[赋值、复制与共享](assignment-semantics.md)中声明的 copy 类：

```el
let point = Point()
```

新构造的 `Point` 直接成为 `point` 持有的结果，不需要先做一个中间对象、再复制一份给 `point`。同一具体类型的按值传参、返回以及嵌套返回和转发也遵循直接交付规则。实际对象仍按最终拥有者的生命周期清理；构造失败时，已完成的部分仍需清理。

## 必要的独立值仍然独立

```el
let original = Point()
let other = original
original.x = 1
other.x = 2
```

这段示意中两个绑定随后都独立使用。复制语义需要维持两个对象的隔离，不能把它们合成一个可变对象来省工作；字段若本身采用共享策略，其共享语义仍按字段合同处理。复制消除不会把 copy 类型变成 shared 类型。

## 不要依赖临时复制的副作用

拥有临时值的隐式复制链允许合并。即使用户定义的复制构造会记录日志、修改外部状态、抛异常或异步执行，被省略的那些临时复制的相应效果也可以不发生；中间对象独有的构造和析构观察也可以消失。程序不能用隐式临时复制的次数实现业务逻辑。原始来源所需的复制、实际资源所有者的释放和借用来源的保活仍然成立。

其他已有语义复制或移动的消除，还须保持结果、身份、别名、借用、异常、外部效果和接管提交。显式调用普通复制函数不因名称或用途自动获得上述临时链省略许可。

## 复制消除和自动移动有什么不同

复制消除避免中间复制；自动移动是在符合条件的最后一次读取处转移已有值。自动移动不等于移动构造也被省略：移动和源清理的副作用仍按各自合同发生。右值也不会因为复制消除跳过类型转换或重载选择。

常见误解是“每个赋值符号都调用一次复制构造”或“优化可以随意删除所有复制副作用”。前者忽略直接交付与临时链合并；后者忽略必要复制、独立对象和其他可观察合同。减少复制可能有性能收益，但具体收益要测量。
