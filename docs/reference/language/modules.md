<a id="imports"></a>

## 导入形式

下列各行展示独立形式，不应在同一模块重复导入相同绑定。

```el
import { run, helper as h } from "file:./tools.el"
import /^run/ from "file:./tools.el"
import /.*/ from "file:./tools.el"
import /.*/ as tools from "file:./tools.el"
```

每种普通导入都明确选择名字。以上分别展示具名导入、正则选择、全量选择和编译期命名空间。EL 没有 `import *`、副作用导入或运行期命名空间值；不能把 `tools` 本身保存、传参或比较。

导入名是只读活绑定。不能给导入名重新赋值；模块内部改变导出变量时，导入方可观察到新值。导出的共享对象仍遵循自身的可变性和同步合同，只读绑定不等于对象深度不可变。

### 导出与重导出

顶层声明用 `export` 公开；普通导入不会自动成为本模块的导出。转发别的模块时使用重导出：

```el
export { run, helper as assist } from "file:./tools.el"
export /^parse/ from "file:./formats.el"
```

重导出保留原声明身份和活绑定，不在转发模块建立普通导入绑定。同一声明经多条路径到达会去重；实际导入的同名函数合并为重载候选，普通变量与参数仍按词法规则遮蔽外层导入。不同声明的非函数名字冲突需要显式改名。

<a id="sources"></a>

## 来源解析与身份

| 来源或映射 | 解析规则 |
| --- | --- |
| `file:./tools.el` | 相对导入模块所在目录解析，不相对进程工作目录 |
| 本地目录或以 `/` 结尾的 HTTP(S) 路径 | 取目录中的 `index.el` |
| 显式源码文件 | 必须使用 `.el` 后缀，不猜测 `name.el` 与 `name/index.el` |
| 项目 `imports` 的相对映射值 | 相对配置文件所在目录解析 |
| `el:` | 统一 `imports` 表中的标准库前缀，可由项目显式覆盖 |

映射先匹配精确键，否则取最长的前缀键；前缀键以 `:` 或 `/` 结尾，对应值必须是目录。环、同键冲突和无效目标报错，不静默回退。`el:` 不授予类型、宏或初始化特权。项目配置及显式入口命令见[工具链](../../toolchain.md)。

模块身份取归一化后的声明来源，获取结果和模块身份分开处理：HTTP(S) 重定向不改声明身份，不同声明来源也不因内容相同而自动共享状态。文件路径消去点段、规范分隔符，但不追随符号链接合并身份，也不猜测大小写相等。内容缓存共享不等于模块实例共享。

一次编译对同一声明来源复用同一已获取版本；缓存校验还涉及映射、源内容、编译器与目标身份。删除缓存只失去复用机会，不能改变程序语义。

### 按目标选择依赖

模块级普通 `if` 或 `switch` 可按编译期可确定的目标信息选择导入。只展开选中分支：未选分支仍做词法与语法检查，但不获取来源、不验证目标 ABI，也不登记导入绑定。目标条件不能无副作用地确定时给出定位诊断，不把全部分支提前导入。

这类静态选择不能放进函数体；函数中执行到 import 时的初始化，遵循下一节的执行位置规则。文本级条件裁剪另见[文件预处理](preprocessing.md)，系统原生库声明另见[外部接口与 ABI](foreign.md)。

<a id="initialization"></a>

## 模块初始化

模块顶层代码就是入口，不要求 `main`。每个来源与版本在一个进程中只有一个模块实例；重复导入共享状态。需要多份业务状态时使用普通类实例，没有显式创建独立模块副本的 API。

顶层语句按源码顺序执行。遇到 import，先取得目标模块的初始化结果；目标尚未开始时递归执行目标内容，完成后回到导入位置。不会把所有 import 或变量初始化集中提到文件开头。默认 prelude 等价于源码之前的一次隐式导入，其名字仍可被本模块普通绑定遮蔽。

循环导入可以使用提前登记的函数，但直接或间接读取尚未初始化的变量仍是模块初始化错误。把读取放进函数并不自动消除问题：若在顶层初始化期间调用该函数，读取可能仍然过早。实际等待环必须诊断，不能永久等待或提供零值。

### 导入失败与捕获边界

普通源码 import 即使位于函数、`try` 或词法块内，也在执行到该位置时取得初始化结果；绑定只在所在词法作用域可见。已知静态来源的源码与接口仍在构建期检查，块内 import 不会把语法或类型错误变成可捕获的运行期失败。

模块初始化器的异常在导入处传播原错误，不统一包装成 `ImportError`。同一来源与版本的并发初始化共享一次结果；失败实例不自动重跑有副作用的初始化。

初始化失败退出模块时，先收束所属活动，再按声明逆序清理已经成功建立的变量。未建立的值不析构，未触发的惰性初始化器不为清理而执行。某个析构失败后仍继续其余清理，按普通析构聚合规则保留原错和清理错误；此前已成功导入的其他模块不被强制销毁。清理资源不回滚已经完成的文件写入或网络请求。

<a id="lazy-imports"></a>

## 惰性具名导入

惰性导入必须列出非空具名表，可以逐项重命名。下列两行分别展示导入与重导出：

```el
lazy import { compute as calculate } from "file:./backend.el"
export lazy import { compute as calculate } from "file:./backend.el"
```

惰性导入不是运行期首次访问才打开模块；编译期名称解析实际选择某个导入绑定时，才按需打开来源模块并使其参与编译。运行期初始化仍遵守模块初始化规则。没有被引用的名字不会触发来源模块。惰性重导出保留延迟关系，消费者实际引用转发名时需求才传递到来源。

`lazy import` 和 `export lazy import` 禁止正则名字选择，即使正则只匹配单个名称也不例外；这是明确的设计限制。普通 `import /pattern/` 与普通正则重导出仍可用。

显式列名让编译器无需探查来源即可知道名称需求应传给哪条边，不能把禁止正则解释为待补功能。参数或局部变量遮蔽后的同名引用不构成导入需求；名称需求不取决于优化器最终是否删除代码。

### 与惰性绑定的区别

`lazy let value = expression` 与 `lazy const value = expression` 推迟的是运行期初始化器，第一次需要值时执行，共享一次初始化结果，失败不自动重试。它们不推迟源码的读取、解析和类型检查，也不保证后续可变值的任意并发访问安全。

惰性导入控制编译期来源边界，惰性绑定控制运行期值的建立，两者不能互相替代。

<a id="updates"></a>

## 更新与保留状态

模块更新采用版本并存与导入入口切换。通过导入入口发起的新调用可进入新版；此前保存的普通函数值保持旧版。已有对象保留所属版本的布局、方法与析构代码，不自动变成同名新版类型。仍被对象、闭包、任务或原生回调持有的旧代码必须继续存活。

默认“严格保持运行”策略在兼容时切换，不兼容则延后激活并保留旧版，不自动重启。依赖组默认整体预检并原子切换入口；这个原子边界不回滚候选初始化已经完成的外部副作用或共享状态写入。

`@preserve(id: "counter", mode: "shared")` 指定跨版本保留绑定，`id` 必填且在模块版本内唯一。只有本次更新的新旧双方都声明同一保留 ID 才匹配，不按变量名或内容摘要猜测。

| 模式 | 新版接收方式 |
| --- | --- |
| `shared`（默认） | 与本次更新源版本共享绑定；候选写入立即可见，失败不回滚 |
| `inherit` | 接收切换时的当前值，此后绑定独立；值仍按自身复制或共享协议处理 |

匹配成功时跳过声明初始化表达式；没有旧值才执行它。去掉保留属性后按普通变量初始化，不建立供以后版本回找的历史槽。保留绑定使用 `scope` 析构策略，不能显式要求 `aggressive`；仍被旧代码使用的值不得提前析构。
