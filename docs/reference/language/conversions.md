# 类型转换

EL 会在调用、运算、赋值和条件判断中寻找可用的转换，但这些位置允许的转换不同。记住两条：普通表达式不会偷偷执行显式转换；条件判断会另外寻找能表达真、假或缺失的类型。

## 先看转换在哪种位置发生

| 位置 | 会考虑什么 | 不会自动做什么 |
| --- | --- | --- |
| 普通调用、运算、赋值 | 标准转换、声明为 `implicit` 的用户转换 | 不调用显式转换运算符或构造器 |
| `Type(value)` | 按目标类型的构造和转换协议选择转换 | 不保证结果一定是目标类型本身；转换可声明返回派生类型 |
| 条件位置 | 到带 `netra`、`xata` 或 `lohk` 属性类型的转换；最多一层显式转换，并可经过隐式转换 | 不把所有条件都硬编码成 `Bool` |

## 普通转换按什么顺序比较

重载候选逐个参数比较转换，优先级从高到低如下。这里的“更好”是比较候选的依据，不是转换失败时的回退顺序。

| 等级 | 含义 | 例子与边界 |
| --- | --- | --- |
| 精确类型 | 实参类型与形参类型相同 | `Number` 形参接收 `Number` 实参，比需要转换的候选更合适 |
| 唯一基类或联合注入 | 派生值转为唯一的基类视图，或值进入可容纳它的联合类型 | 只有一条最短且唯一的基类子对象路径才可用；多条同样短的路径不能靠猜选一条 |
| 结构接口 | 值满足接口声明的完整方法和调用合同 | 比较参数、结果、接收方式、异常等合同的包含关系，不按成员数量打分 |
| 用户隐式转换 | 源类型的 `implicit operator`，或目标类型合格的 `implicit constructor` | 每条路径最多一层用户隐式转换；其前后可以有标准转换 |
| `any` 装入 | 把具体值装入动态类型容器 | 只在更具体的候选都不适用时考虑 |

转换运算符和构造器默认是显式的。普通调用里只有声明了 `implicit` 的转换才参加候选；`Type(value)` 则是源码明确要求按目标类型协议转换。

```el
let countText = Text(3)
let label = "count: " + countText
```

`Text(3)` 明确把数值转换成文本。直接写 `"count: " + 3` 不会因为左边是 `Text` 就自动转换右边；标准库没有默认的 `Text` 与 `Number` 混合加法。该表达式只有在程序另有适用的用户重载时才可能成立。

## 哪些构造器能参与隐式转换

目标类型的隐式构造器必须声明为 `implicit`，并恰有一个固定、有类型的普通值参数；该参数可有默认值。它不能是同类型复制构造。`any` 或无类型参数不是隐式转换入口；有多个参数、只是其中一个必需的构造器也不算单参数转换构造。准入该构造器参数时只允许标准转换。

如果源类型转换运算符和目标类型隐式构造都能转换同一个实参，两者同阶；若其他规则无法分出唯一优者，结果是歧义。编译器不按声明顺序偏选一方。选中转换后执行失败或抛异常，会沿普通错误路径传播，不会改试另一个候选。

## 转换返回派生类型时会怎样

转换运算符可以声明返回 `Derived`，而调用者写 `Base(value)`。只有返回类能经唯一基类路径视作 `Base` 时，这种写法才成立；无关返回类型或有歧义的基类路径不成立。表达式保留运算符实际声明的返回类型，之后存入 `Base` 类型的绑定时再按普通存储和生命周期规则处理。

## 条件属性分别表示什么 {#conditions}

条件判断不是要求结果必须叫 `Bool`。EL 查看类型上的条件属性，并按属性决定控制流：

| 属性 | 在条件中的作用 | 内置值的常见例子 |
| --- | --- | --- |
| `xata` | 表示条件为真，执行真分支 | `t_t` 上的实例 `t` |
| `netra` | 表示条件为假，执行假分支 | `nil_t` 上的实例 `nil` |
| `lohk` | 表示缺失或无结果；`void` 条件按假处理 | `void_t` 上的实例 `void` |

条件转换搜索可经过一层显式转换，也可包含隐式转换。标准库中的 `Number` 提供到 `Bool` 的显式转换；`Bool` 本身就是联合类型 `t_t | nil_t` 的别名，结果已经是其中一种值，不存在“从 Bool 再转到该联合”的额外步骤。条件位置允许使用这条显式转换，不表示普通算术也会自动使用它。`Text` 和标准数组也按各自的转换协议提供条件判断；其他类型可显式检查长度或定义自己的转换。

```el
let success: Bool = t
let failure: Bool = nil
```

这里 `t`、`nil` 是值，`t_t`、`nil_t` 是它们的类型；类型别名写作 `t_t | nil_t`。同名的 `Bool(value)` 函数则按输入的条件行为返回 `t` 或 `nil`，与“Bool 是什么类型”是两个问题。

带 `xata` 和 `netra` 的值分别选择真、假分支。类型同时带这两个属性时，两个分支都会执行，真分支结果作为左操作数、假分支结果作为右操作数传给 `operator&` 合并；不能把这种情况当成普通二选一。只有 `lohk` 属性的类型用于表示无结果，不代表真值。内置机制需要产生真值、假值或无结果值时，使用声明顺序中第一个带相应属性的实例；编译器不会凭空造实例。

## `void`、`nil` 与联合条件怎么区分

`nil` 是一个假值；`void` 是缺失或无结果值。二者在条件中都走假分支，但类型和用途不同。对于 `T | void_t` 这样的可能缺失值，条件先判断值是否缺失：缺失路径直接按假处理，在场路径再按 `T` 的条件转换判断。

因此缺失路径本身不需要 `netra` 或 `xata` 实例。若程序需要产生一个假值、真值或无结果值作为表达式结果，则必须定义对应属性的实例；缺少所需实例或没有合法转换路径时，条件使用报错。多个同等适用的转换路径也报歧义，转换搜索会检测循环。

条件转换本身可以抛异常或挂起；这些效果会进入调用属性推断。
