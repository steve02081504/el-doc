# 为什么 EL 没有异或

> 在二进制机器上，合并一份掩码和撤销一份掩码可以用同一条指令。在三进制机器上，照抄这条规则就会把结果算错。

EL 的目标是能编译到任意进制的芯片，而不是要求非二进制芯片假装自己是二进制。EL 的“dit”指目标表示的一位。EL 提供 `dit_add_mod` 和 `dit_sub_mod`：一个逐位组合，一个逐位撤销。二进制后端可以把两者都实现成机器 XOR；EL 和 EIR 不把那条机器指令当成通用的数值原语。这是语言的目标，不代表目前已有任意进制的可用后端。

## 二进制碰巧让加和减得到同一个结果

设一位有 `R` 种状态，取值是 `0` 到 `R - 1`。逐位模加，在每一位上算 `(a + b) mod R`；逐位模减，在每一位上算 `(a - b) mod R`。这里的模取非负余数。每一位各算各的：不进位，也不借位。这不是先做普通整数加减，再截掉整字的溢出位。

| 单位数位的输入 | 模加 | 模减 |
| --- | --- | --- |
| 二进制：`0` 和 `1` | `1` | `1` |
| 二进制：`1` 和 `1` | `0` | `0` |
| 三进制：`0` 和 `1` | `1` | `2` |
| 三进制：`1` 和 `1` | `2` | `0` |

二进制里，`+1` 和 `-1` 模 2 都等于 `1`。所以这两种运算的真值表完全相同，都是「两位不同则为 1」。三进制里，`+1` 和 `-1` 分别变成 `1` 和 `2`，就不能再拿同一种操作兼任两件事了。比如三进制 `12₃` 和 `21₃` 逐位模加得 `00₃`，逐位模减得 `21₃`。两种结果都与普通整数加减不同。

## 看你是在组合、撤销，还是处理二进制数据

| 你要做的事 | 用什么 |
| --- | --- |
| 把两份目标数位的贡献合成一份，例如在对齐位置后合成两个结构哈希 | `dit_add_mod(a, b)`。模加可交换、可结合，合并可分批做。 |
| 已知合成结果和其中一份贡献，求另一份 | `dit_sub_mod(combined, known)`。被减数写在前面，结果可重新合成；模减一般不可交换，也不可结合。 |
| 两个布尔条件恰好一个为真 | 对两个 `Bool` 用 `a != b`。你要的是“不相等”，不是目标数位运算。 |
| 求两个集合中恰好属于其中一个的元素 | 用集合的对称差，如 `left.symmetricDifference(right)`。 |
| 实现规定了二进制位或八位组的格式，例如 ChaCha20 | 用格式或算法自己的接口和位宽规则。目标是三进制时，格式中的二进制位也不会变成三进制数位。 |
| 计算需要进位或借位的整数和、差 | 用普通的 `+`、`-`。 |

下面的例子用掩码组合和恢复原值。第一行的值会随编译目标变化，第二行不变：

```el
import { dit_add_mod, dit_sub_mod } from "el:number/dit-operations.el"

let combined = dit_add_mod(1, 1)
console.stdout.writeLine(combined)                    // 基数 2：0；基数 3：2
console.stdout.writeLine(dit_sub_mod(combined, 1))  // 两种目标都得 1
```

更一般地，先模加 `b`，再模减同一个 `b`，就能还原 `a`。在二进制代码里，连续 XOR 两次可以还原原值，恰恰是因为第二次 XOR 也等价于模减。移植时，如果第二次是在撤销，就把它写成模减，不要把两次都替换成模加。

对实际芯片的数位，还可以定义逐位最小、逐位最大。在基数 2 时，它们对应 AND、OR；在更高基数时，它们是对数字大小的运算，不是二进制位掩码。EL 将它们写成 `dit_min`、`dit_max`；EL 和 EIR 都不提供通用位与、位或、位非或异或。

逐位取反也能用模减表达，前提是你选的是「最大数码减当前数码」这种定义。以三进制三位为例：掩码是 `222₃`，逐位减去 `012₃` 得 `210₃`。基数 2 时，用模加同样能执行这类取反；基数 3 时，模加固定数码只会让数码循环，不能做出这个翻转。这不是在重新定义布尔的 `!`。

## 基数由表示决定，不由调用者指定

普通 `Number` 使用产物目标的 `dit_radix()`，不是编译器正在运行的机器的基数，也没有 `radix:` 参数。两个操作数必须是有限整数。基数 2 的 `Number` 支持负数，按无限符号扩展的二补码处理；其他基数的普通 `Number` 只接受非负整数，高位补零。

EIR 的 `dit.min`、`dit.max`、`dit.add.mod` 和 `dit.sub.mod` 则以操作数绑定的整数表示为准，使用该表示的基数和宽度。数值上写成 `0b1010` 只是在用二进制记法写同一个整数，不会让普通 `Number` 改用基数 2。EL 中 `Number` 的 `^` 仍是乘方，`DitSet` 不提供 `&`、`|`、`!` 或 `^` 的按位重载；它的同宽 `+`、`-` 分别是逐位模加、模减。
