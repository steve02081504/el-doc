# 读语言之前

语言部分从这一页开始。先看一段在规范上**没有规定结果**的代码。

## 先猜一个输出

```el
const a = 1
a = 2
console.stdout.write(a)
```

猜 `2`？`1`？还是什么都不输出？

!!! danger "答案是：未定义"
    规范（SYN-78）把对 `const` 槽位的重赋、复合赋值、步进和经别名写回都列为**未定义行为**。程序走到这里就没有规定的结果了：`a` 可以是任何值——`2`、`1`、上一次运行留下的东西，或者让后面某一行崩掉。语言不承诺它打印什么，也不承诺它在哪里停下。

## 谁负责发现这种错误

`elc` 和 `el run` 把源码翻译成可执行的东西并按规范执行；它们**不保证**为未定义行为报错（SYN-78 原文：ELC 不保证报错）。所以别指望编译器兜底：它不会先停下来替你做一遍检查，这类程序可能一路跑下去，把未定义的结果当成正常输出。

对能确定的违规报错的是格式化器 `elf`，命令入口是 `el formatter`：

```sh
el formatter --check hazing.el
```

它同时检查格式、`unsafe` 许可与可简化写法，并复用同一套语义分析；发现需要处理的内容或规则违规时以非零退出码结束，可以直接放进提交前检查或 CI。详细的退出码见[工具链](../toolchain.md)。对无法判定的情况，它必须明确报告“未知”，不能假装检查过。

!!! warning "能运行不等于正确"
    `el run` 跑通只说明这段代码被翻译并执行了，不说明它没有踩未定义行为。**示例能跑只是起点，`el formatter --check` 干净才算写完。**
