> 一枚棋子明明走得出那一步，为什么程序仍应拒绝？因为走完后己方王可能暴露在攻击线上。

## 先实现马的规则

坐标从零开始，列 0 是 a 列，行 0 是第 1 横线。保存为 `knight.el`，运行 `el run knight.el`。这个例子的唯一占用格是己方棋子所在的 b3。

```el
fn knightMove(fromX: Number, fromY: Number, toX: Number, toY: Number): Bool {
	let dx = toX - fromX
	let dy = toY - fromY
	let xSquared = dx * dx
	let ySquared = dy * dy
	return (xSquared == 1 & ySquared == 4) | (xSquared == 4 & ySquared == 1)
}

for let rank in ..8 {
	for let file in ..8 {
		if (!knightMove(0, 0, file, rank)) continue
		if (file == 1 & rank == 2) continue
		console.stdout.writeLine(file, ",", rank)
	}
}
```

预期只显示 `2,1`，也就是 c2。删除跳过 b3 的条件后，第二行应为 `1,2`。

## 从单枚棋子扩展到整盘

1. **描述棋局。** 记录每格的棋子、行棋方、易位权、吃过路兵目标格，以及重复局面的记录和无兵移动或吃子半回合数。搜索基于快照推进，每次应用候选走法都更新这些状态。
2. **生成候选。** 车、象、后沿方向扫描，遇到第一枚棋子后停止。马使用上面的跳跃规则。兵的前进要求目标格空，斜向攻击格则由阵营的前进方向和列差决定。
3. **验证合法性。** 在候选走法应用后的局面上查对方的攻击格，过滤己方王处于攻击下的局面。易位还要验证王出发、经过和到达的格子。吃过路兵须先从正确的格子移除被吃的兵，再检查王是否被攻击。
4. **按规则评分。** 先识别将死、和棋，其余局面按子力、王的安全和活动度评分。用极小极大逐层看对手应对，记录已完成的深度和触发的评分规则。搜索预算用完时只返回上一次完整深度的选择。
5. **接入窗口。** 提交走法前比较局面编号。重开、悔棋或对手落子都会改变编号，迟到的旧答案直接丢弃。

| 测试棋局 | 应看到的结果 |
| --- | --- |
| 白王 e1、白车 e2、黑车 e8、黑王 a8，白方走 | 白车不能离开 e 列暴露白王 |
| 黑王 h8、白王 f7、白后 g7，黑方走 | 无合法走法且受攻击，判将死 |
| 黑王 h8、白王 f7、白后 g6，黑方走 | 无合法走法且未受攻击，判逼和 |
| 白兵 e5、黑兵 d5，黑兵刚从 d7 到 d5 | 白兵候选有 e5 到 d6，走后应删除 d5 的黑兵，并照常核对王的安全 |
