# 第一个程序：让电脑显示一条提醒

> 先写一条明天用得上的提醒，保存、运行，再把它改成自己的话。

!!! abstract "🎯 读完这页，你能"
    - 区分终端命令、EL 代码和程序输出
    - 保存一个 `.el` 文件，并在它所在的文件夹运行
    - 修改文字后重新运行，按现象排查常见问题

    <span class="el-chip">可以分步完成，不计时</span> <span class="el-chip">前置：一台电脑和可用的 EL 工具</span>

## 先确认工具已经准备好

EL 还在开发中。这份教程不提供安装包，也不把源码仓库当成可直接运行的发行包。如果你还没有 EL 工具，请先请提供工具的人协助准备，并确认最小程序能运行；不用为了学第一课先自行构建编译器。

已经拿到工具时，使用配套说明支持的系统。下文以 Windows 为例；其他系统也需要先确认对应工具可用。平台设计目标与当前验收范围见[规范与实现边界](appendix/implementation-status.md)。

**终端**是可以输入命令、查看运行结果的窗口。Windows 可以从开始菜单打开 PowerShell。在里面输入下面这行，再按回车：

```powershell
el --help
```

这是**终端命令**，不写进 EL 文件。能看见帮助信息，说明终端找到了 EL；这一步还不能证明编译和运行都可用。

如果提示找不到 `el`，工具可能没有安装好，或者它的文件夹还没加入 `PATH`。`PATH` 是系统寻找命令的文件夹清单。先按工具附带的说明检查，必要时请协助安装的人处理；这一关卡住不需要修改后面的代码。

## 第一步：保存一份代码文件

1. 在文档目录里新建文件夹 `el-practice`。把练习放在这里，之后容易找到。
2. 打开纯文本编辑器，例如 Windows 记事本。不要使用 Word。
3. 输入下面这一行代码。
4. 选择“另存为”，保存到 `el-practice`，文件名填 `hello.el`，文件类型选“所有文件”，编码选 UTF-8。

```el
console.stdout.writeLine("明天记得带水杯")
```

这段是 **EL 代码**，保存在文件里。`console.stdout.writeLine(...)` 的作用是显示一行文字，双引号包住要显示的内容。先保留这句英文，只改引号里面的文字就可以。

在 Windows 文件资源管理器里打开“查看 → 显示 → 文件扩展名”，确认它叫 `hello.el`，不是 `hello.el.txt`。不同 Windows 版本的菜单位置可能稍有不同；文件扩展名是名字末尾的 `.el` 或 `.txt`。

## 第二步：在同一个文件夹打开终端

用文件资源管理器打开 `el-practice`。在地址栏输入 `powershell`，按回车，就会在这个文件夹打开终端。也可以在 Windows 11 文件夹空白处右键，选择“在终端中打开”。

先输入下面的命令，确认这里确实有代码文件：

```powershell
Get-ChildItem hello.el
```

应看到 `hello.el` 的文件信息。如果提示文件不存在，先检查保存位置和文件名；不用继续运行。

## 第三步：请电脑执行代码

在终端输入：

```powershell
el run hello.el
```

`el` 是工具名，`run` 表示运行，`hello.el` 是要运行的代码文件。不要把这行写进 `hello.el`，也不要额外输入示例中没有的 `>` 或 `$`。

预期输出：

```text
明天记得带水杯
```

这段是**输出**，只用来核对结果，不需要输入。EL 文件最外层的代码就是入口，第一课不用额外写 `main` 函数。

如果显示的是错误信息而非提醒，先停在这一步，按后面的表检查。教程中的预期输出是核对目标，不代表已经在你的工具版本上验证成功。

## 改成你自己的提醒

回到编辑器，把引号里的文字改成 `放学后还书`。保存文件，再到终端按向上方向键找回上一条运行命令，按回车。

你应该看到：

```text
放学后还书
```

旧文字还在终端历史里是正常的，只看最新一次运行的结果。如果最新结果仍是旧文字，检查是否保存、是否打开了另一个同名文件。

## 自己补第二条提醒

在代码下面另起一行，再写一句输出，让一次运行显示两行：

```text
放学后还书
晚上整理书包
```

??? tip "提示：先试，再展开"
    每条输出指令各显示一行。第一行保留，第二行也用同样的英文写法，把引号里的文字换掉。

??? success "参考代码"
    ```el
    console.stdout.writeLine("放学后还书")
    console.stdout.writeLine("晚上整理书包")
    ```

## 卡住时，按现象检查

错误文字可能随版本变化。先看第一条错误，不要求背诊断英文。

| 你看到的现象 | 先做什么 |
| --- | --- |
| 提示找不到 `el` 或无法识别命令 | 回到工具准备，确认安装和 `PATH`；重新打开终端 |
| 提示找不到 `hello.el` | 用 `Get-ChildItem hello.el` 核对当前文件夹，再看是否存成 `.el.txt` |
| 提示引号、括号附近有错误 | 对照完整代码，使用英文半角 `"`、`(`、`)`，检查大小写 |
| 改了文字，结果没变 | 保存编辑器里的文件，确认终端运行的是这个文件 |
| 帮助可用，但运行提示缺少编译服务或标准库 | 工具可能不完整；保留完整错误，交给提供工具的人检查 |
| 文件与写法都核对过，仍然失败 | 保留代码、完整命令和第一条错误，请人协助判断工具版本与实现状态 |

求助时可以这样说明：“我在 `el-practice` 里运行 `el run hello.el`，原本希望显示提醒，实际看到下面的错误。”贴代码和错误文字之前检查有没有个人路径等不想公开的信息。

## 带走这三样

- 代码存进 `.el` 文件，命令输入终端，输出用来核对。
- 保存文件之后，再运行 `el run 文件名.el`。
- 先确认运行的是正确文件，再检查写法和工具状态。
