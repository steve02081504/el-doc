# 从源码注释生成 API 文档

标准库参考按库分类、模块路径、符号名字和[默认环境](api/environment.md)提供查询入口，均从同一模型生成。标准库的接口说明与实现放在一起。生成器读取 `src/stdlib/**/*.el`，输出[API 参考](api/index.md)及同源 JSON；教程继续负责学习路线，不复制每个接口的合同。

本方案服从 EL 的 `docs/spec/12-syntax.md` DOC-1 至 DOC-8、`docs/spec/11-build-and-toolchain.md` CLI-5.2 至 CLI-5.5 和 `docs/design/wiki-object-model.md`。Python 工具是 el-doc 的过渡提取器，标签是注释内的作者约定，不新增编译器语法或另一套示例测试语言。

## 写一份能直接阅读的注释

使用独占一行的 `///`，紧邻被说明的声明，放在声明属性之前。开头给名字，正文说明用途，再按需要补参数、返回值、异常、复杂度和示例。类型、默认值和声明修饰从源码提取，不在标签里重复维护。

````el
/// @api over
/// 创建一个二元函数：先分别变换两个输入，再合并变换结果。
/// @param merge 接收两个变换结果的二元可调用值。
/// @param transform 接收单个输入的可调用值。
/// @returns 返回 merge 结果的二元函数。
/// @example 比较两个数的平方
/// ```el
/// let largerSquare = over(max, value => value * value)
/// console.stdout.writeLine(largerSquare(-3, 2))
/// ```
/// 预期标准输出：
/// ```text
/// 9
/// ```
export fn over(merge, transform) {
	return fn(left, right) {
		let transformedLeft = transform(left)
		let transformedRight = transform(right)
		return merge(transformedLeft, transformedRight)
	}
}
````

这是当前标准库接口的写法示范，输出是按源码推导的预期值，未运行验证。完整合同见生成的 `over` 条目。注释属于普通行注释，不增加语言语法或编译副作用。

| 标签 | 含义 |
| --- | --- |
| `//! @module 标题` | 模块说明，后续正文也用 `//!`，每个文件最多一个 |
| `@api 名字` | 后续声明的文档；成员写 `Type.member`，重载写 `name~label` |
| 正文 | 必填的用途摘要，后续段落可使用 Markdown |
| `@param 名字 说明` | 参数语义、单位、取值范围、所有权等；按声明顺序书写 |
| `@returns 说明` | 返回值及其合同 |
| `@throws 说明` | 失败条件、异常传播与已发生的副作用 |
| `@complexity 说明` | 时间、空间或回调次数；有前提就明确写出 |
| `@note 说明` | 平台限制、生命周期、线程要求等必要补充 |
| `@example 标题` | 一个完整的 `el` 代码围栏，可跟一个 `text` 预期标准输出围栏 |
| `@see 模块路径::名字` | 引用已生成条目，例如 `functions/composition::over`；模块引用省略 `::名字` |

每个 API 至少有一个示例；可以重复 `@example` 展示正常、空输入和失败情形。示例用三个反引号围栏，代码中的 `@` 不会被当成文档标签。`text` 围栏只表示预期标准输出；返回值、异常和解释写在正文或代码注释中。生成器不执行示例，所有示例的验证状态均为 `not-run`。

普通 `//` 留给实现说明。不要将所有内部注释自动发布，也不要用文档标签改变运行行为。参数名不应再带一份类型；无已知复杂度证明时不要凭直觉填写 `O(1)`。重载标签选语义名字，不能使用行号或计划编号。

## 生成与检查

在 el-doc 根目录运行，明确指定实际 EL 检出：

```text
python scripts/stdlib_docs.py --el-root /path/to/el
python scripts/stdlib_docs.py --el-root /path/to/el --check
python -m unittest discover -s tests -v
python scripts/build_site.py build
```

只依赖 Python 3.10 及以上版本的标准库。默认写入 `docs/stdlib/api`，也可以用 `--output` 指定独立目录。输出是确定性的 UTF-8/LF；未变化页面不重写。生成前检查所有文档与引用；格式错误、重复身份、悬空引用及过期检查均返回非零状态。

每个条目提供「在 GitHub 查看源码」，默认跳转 EL 仓库 `master` 分支的对应文件和声明行；模块条目定位到模块注释行。可用 `--source-url` 指定其他仓库、分支或提交下的 `src/stdlib` URL 前缀。行号对应生成时的源码，发布文档时应同步推送源码注释。

`.generated.json` 记录本生成器拥有的文件及摘要，只清理清单中的过期页面，保留其他文件。手改过的生成文件会阻止覆盖；请把修改迁回源码注释，恢复该文件至原生成内容后再生成。每个文件通过同目录临时文件替换；整个目录不是事务，写盘中断后需检查受影响文件再重新生成。

生成快照随 el-doc 提交，因此没有 EL 检出的环境也能构建参考站。更新接口文档时需同时提交对应 EL 注释与新的文档快照。CI 检查生成器测试和站点构建；它不下载另一个仓库的浮动分支，也不声称快照与最新 EL 自动同步。

## 数据如何供 CLI 与 GUI 共用

`api.json` 是过渡工具渲染之前的文档模型，无绝对路径或网页布局依赖。它不是未来原生 Wiki 对象的持久格式，也不提供编译器声明身份证书：

- `source_digest`：按相对路径排序的全部源码文件路径与 SHA-256 摘要列表的摘要，识别输入内容；不是编译器验证证明。
- `files`：已标注文档文件的相对路径和内容摘要。
- `entries`：模块和 API 的 `id`、名字、源码位置、原始签名片段及有序 `sections`。
- 声明元数据：`initializer` 保存可安全分离的变量初始化表达式，`value_type`、`owner` 和 `return_type` 保存词法可识别的变量类型、文档成员归属和返回类型；未知项为空。这些字段不是编译器类型检查结果。
- `environment`：从标准库入口的显式重导出名字表追踪默认可见名字、原声明位置及可对应的文档身份。同模块重载族保留为一组；未解析或来源有歧义时保留名字而不猜定义。
- `exports`：模块公开名字到原已注释 API 身份的词法映射，支持显式重导出别名；未解析的项目不发布映射。
- `types`：类、接口、枚举、类型别名与类型工厂的源码声明，包含未写 API 注释的定义；[类型索引](api/types.md)展示原始声明与可安全提取的初始化表达式。
- `type_references`：API 声明的类型表达式内各名字及其定义来源；按声明所在模块的本地绑定、导入和词法作用域解析，联合和泛型表达式中的名字分别链接。泛型类型参数、长度等值参数链接到所属声明；条件重导出链接到实际选择规则，不擅自选定目标分支。未知来源不按全库同名猜测。
- `sections`：`tag`、`value`、`markdown`；示例还包含 `code`、可空的 `expected_stdout` 和 `verification`。
- `coverage`：扫描文件数、已标注文件数和 API 条目数；不伪装成全库公开符号覆盖率。

API 身份采用“相对模块路径去掉 `.el` + `::` + 文档名字”，成员限定名和重载标签由作者明确指定。网页锚点由身份摘要生成，移动行号不破坏链接；改模块路径或重载标签会改变身份。该格式是内部模型，不提供旧版兼容承诺。

## 从代码跳到定义与说明

EL 代码块中的点状下划线表示可点击的参考链接。例如 `console.stdout.writeLine` 的三个名字分别链接变量、成员端口与写入方法；声明页的类型字段继续链接可唯一识别的类型条目。链接在构建时生成，复制代码时仍得到原来的纯文本。

`scripts/build_site.py` 先验证生成快照完整，再由 Zensical 构建页面，最后生成代码跳转并验证站内链接。`hooks/code_links.py` 消费同一份 `api.json`：默认名字来自 `environment`，具名导入及别名通过 `exports` 和原模块定位，已知成员链通过声明类型与返回类型继续查找。显式简单类型注解可用于定位局部变量的成员，但变量本身不冒充某个全局 API。语言关键词和相关属性链接到对应语言参考。

这不是编译器的语义导航。局部声明和函数参数遮盖默认名字时保守取消链接；未知接收者、复杂类型推断、宏生成成员和无法确定的导入保持原样。字符串、模板和注释不生成符号链接。构建结束会对实际生成的代码链接逐项检查页面与锚点，缺失即构建失败。

未来由 EL 实现的 `el docs` 沿用现有合同，以编译器词法信息和真实声明身份取代 Python 提取器。生成普通 Wiki 对象，以 EOL 可读保存、EOD 打包，连同标准或自定义 EL reader 经普通后端编译；`--target` 省略时为宿主目标，`--dump eol|eod` 只导出数据。CLI 与 GUI 消费同一对象，提供查询、搜索、源码跳转、模块导航、合同和示例；展示层不解析生成的 HTML，也不重新扫描源码。reader 实施服从既定核心、自举、后置测试及 GUI/目标能力的顺序。

编译器接入后，应按实际目标和条件编译结果计算可见接口，关联重导出、宏展开、继承与重载，并检查参数文档与声明的一致性。示例验证共用标准测试注册、身份、原始模块上下文、权限与隔离，不另造执行器；显式区分运行、仅编译、预期诊断和纯示意，记录输入摘要、工具身份及结果。浏览或生成文档本身不运行源码。

## Python 提取器的边界

当前脚本识别行注释、块注释、普通字符串、原始字符串、模板及其插值、导入正则，避免从这些文本中的 `///` 生成假文档。声明签名是词法片段：支持属性和跨行参数，在顶层函数体、赋值或完整声明行结尾处结束。复杂返回类型和宏生成声明需要未来编译器支持，不把此片段当作类型检查结果。

`syntax` 声明本身可以标注，例如 `rules`、`search`、`batch` 和 `grammar`；页面展示真实的语法入口声明，具体使用方式放在注释示例中。脚本不会运行这些语法扩展或枚举它们生成的成员。

当前提取范围仅为带明确标签的 `///` 声明组和 `//!` 模块组。规范允许的 `/** */` 与独立 Markdown 文档元数据尚未接入此脚本；普通块注释只参与词法屏蔽。Python 文档 ID 是过渡索引键，不能用它按同名匹配来替代未来编译器原声明身份。

脚本只检查简单具名声明的末级名字，不推断成员所在类型、不解析参数合同、不验证作者指定的成员限定名，也不计算真实导出集合。已标注文件如含预处理指令则明确拒绝，防止把未激活分支发布成可用 API。条件语句、平台分支和宏语义也不由脚本求值；此类接口的文档必须由作者注明适用条件。

标准库目前只是开始补文档；生成首页报告当前覆盖范围。没有注释的接口不会获得杜撰说明或自动拼凑的示例。
