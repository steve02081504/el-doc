# 钱够不够买

> 算出余额之后，还需要一句明确的提醒：可以买，还是要再攒钱？

!!! abstract "🎯 读完这页，你能"
    - 用 `>=` 比较预算和总价
    - 用 `if` 和 `else` 显示两种提醒
    - 检查钱够、不够、刚好三种情况

    <span class="el-chip">一次只改一种情况</span> <span class="el-chip">前置：[零花钱还剩多少](budget.md)</span>

## 先把生活里的规则说清楚

规则是：如果预算大于或等于总价，显示余额；否则显示还差多少钱。“如果”写成 `if`，“否则”写成 `else`，`>=` 表示“大于或等于”。

新建 `decision.el`，保存完整程序：

```el
let budget = 20
let price = 4
let quantity = 3
let cost = price * quantity

if (budget >= cost) {
	console.stdout.writeLine("可以买，还剩 ", budget - cost, " 元")
} else {
	console.stdout.writeLine("还差 ", cost - budget, " 元，先不买")
}
```

运行：

```sh
el run decision.el
```

预期输出：

```text
可以买，还剩 8 元
```

## 电脑只走其中一条路

先计算 `cost`，得到 `12`。然后检查括号里的 `budget >= cost`，也就是 `20 >= 12`。这个条件成立，就执行第一对 `{ }` 里面的指令；`else` 后面的指令这次不执行。

花括号把属于同一部分的指令包起来。里面的代码向右缩进，方便你看清它属于哪条路。括号、逗号、引号都要使用英文半角符号。

## 你来改一处：买 6 本

把数量改成 `6`，先算总价，再预测提醒，最后保存并运行。

??? question "核对答案"
    总价是 `24` 元，`20 >= 24` 不成立，走 `else`，输出 `还差 4 元，先不买`。差额用总价减预算，才能得到正数。

## 你来检查边界：钱刚好够呢

把数量改成 `5`。这里总价和预算都是 `20`。这类规则刚好发生变化的位置，叫作**边界**。

??? question "核对答案"
    输出 `可以买，还剩 0 元`。因为 `>=` 包括相等。如果误写成 `>`，钱刚好够时也会被判成不够。

不是只有“程序能启动”才算完成。下面三次运行都符合规则，才说明这个提醒至少覆盖了这三种情况。

| 预算 | 单价 | 数量 | 应看到的提醒 |
| --- | --- | --- | --- |
| 20 | 4 | 3 | 可以买，还剩 8 元 |
| 20 | 4 | 6 | 还差 4 元，先不买 |
| 20 | 4 | 5 | 可以买，还剩 0 元 |

## 补一步：让提醒更适合阅读

原程序计算不变，只在两条输出里各加上 `"本次采购："`。数量为 6 时应输出：

```text
本次采购：还差 4 元，先不买
```

??? tip "提示"
    可以把这段文字放进每条 `writeLine` 的第一个字符串。不要把输出语句移到花括号外面，否则可能失去两种情况的区别。

## 换个任务：阅读目标达到了吗

收起上面的程序，新建 `reading-goal.el`。用变量记录目标页数 `20`、实际阅读页数 `15`。达到或超过目标时显示 `今天的阅读完成了`，否则显示 `还差 5 页`。读到 `20` 和 `25` 页时都应显示完成。

??? tip "卡住时看提示"
    比较实际阅读页数和目标页数；未完成时，用目标减实际。把采购里的“预算”和“总价”换成新问题对应的数据，不用照抄变量名。

!!! success "检查点"
    - [ ] 能指出条件、成立时执行的部分和不成立时执行的部分
    - [ ] 采购程序通过上面三种情况
    - [ ] 阅读提醒在 15、20、25 页时都符合要求

## 带走这三样

- `if` 检查条件，`else` 处理条件不成立的情况。
- `>=` 包括相等，`>` 不包括相等。
- 检查普通情况，也检查规则刚好变化的位置。
