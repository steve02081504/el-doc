# 把阅读记录加起来

> 三天分别读了 12、8、15 页。再增加一天，合计能不能自己跟着变？

!!! abstract "🎯 读完这页，你能"
    - 用数组保存一份阅读清单
    - 用循环逐项累加，并显示计算过程
    - 增删记录后核对总页数

    <span class="el-chip">可以边画表格边读</span> <span class="el-chip">前置：[钱够不够买](decisions.md)</span>

## 一份清单，加上一条重复的规则

**数组**是在程序里按顺序保存多项数据的清单。在 EL 里，`@[12, 8, 15]` 就是一份有三项的数组，项与项之间用英文逗号隔开。

**循环**让电脑对清单里的每项重复做同一件事。这里重复的事是“把当天的页数加到合计里”。

新建 `reading.el`：

```el
let pages = @[12, 8, 15]
let total = 0

for (let today in pages) {
	total = total + today
	console.stdout.writeLine("加入 ", today, " 页，目前共 ", total, " 页")
}

console.stdout.writeLine("合计：", total, " 页")
```

运行 `el run reading.el`，预期输出：

```text
加入 12 页，目前共 12 页
加入 8 页，目前共 20 页
加入 15 页，目前共 35 页
合计：35 页
```

## 用手指沿着程序走一遍

`for (let today in pages)` 表示：按顺序取出 `pages` 中的每一项，这一轮把它叫作 `today`，再执行花括号里的代码。执行完这一轮，才取下一项。

| 这一轮 | `today` 是多少 | 加之前的 `total` | 加之后的 `total` |
| --- | --- | --- | --- |
| 第 1 轮 | 12 | 0 | 12 |
| 第 2 轮 | 8 | 12 | 20 |
| 第 3 轮 | 15 | 20 | 35 |

`total = total + today` 先取出旧合计，加上今天的页数，再把结果存回 `total`。它也可以简写成 `total += today`，意思相同；这页先用完整写法。

`total` 在循环**外面**创建，所以每一轮都能继续使用上一轮的合计。最后一行也在循环外面，因此只显示一次最终结果。

## 你来改一项，再增加一项

先把第二项 `8` 改成 `10`，合计应为 `37`。再在末尾增加第四项 `5`，数组成为 `@[12, 10, 15, 5]`，合计应为 `42`。循环的写法不需要改。

??? question "先想想：清单里有一天是 0，会怎样？"
    仍然会走一轮，只是合计不变。例如 `@[12, 0, 15]` 的合计是 `27`。没有阅读的那一天也可以如实记录。

## 找出这个错误：为什么最后只有 15

这是一个**故意写错的独立例子**。先读，不用覆盖原文件：

```el
let pages = @[12, 8, 15]
for (let today in pages) {
	let total = 0
	total = total + today
	console.stdout.writeLine(total)
}
```

??? question "展开解释"
    它依次打印 `12`、`8`、`15`。每轮开始都重新创建一个为 0 的 `total`，上一轮的合计没有留给下一轮。要累计，就把 `let total = 0` 放回循环前面。

## 收起例子，统计本周运动时间

新建 `exercise.el`，记录三次运动的分钟数 `10`、`15`、`20`，显示 `运动合计：45 分钟`。再增加一次 `5` 分钟的记录，结果应为 `50` 分钟。

??? tip "提示"
    数据的意义变了，累加规则没变。用清楚的名字记录运动分钟数，合计从 0 开始。

!!! success "检查点"
    - [ ] 能逐轮写出阅读例子的合计：12、20、35
    - [ ] 新增记录时只需要改清单
    - [ ] 能解释累计变量为什么要放在循环外面

## 带走这三样

- 数组保存多项数据，循环逐项处理。
- 累加时把上一轮结果留在循环外的变量里。
- 临时打印每轮数据，可以看清程序在哪一步算错。
