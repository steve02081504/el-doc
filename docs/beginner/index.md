# 从零开始：让电脑帮你做事

> 想知道买完文具还剩多少钱？先让电脑替你算一次，再学会自己改规则。

!!! abstract "🎯 走完这条路线，你能"
    - 保存、运行和修改一个 EL 文件
    - 用数字、判断、清单和函数写一个采购小助手
    - 根据结果检查自己的程序，找出改错的位置

    <span class="el-chip">每次一小节，按自己的速度来</span> <span class="el-chip">前置：会打字、会加减乘除</span>

这里不要求你学过编程。**程序**就是写给电脑的一组指令；**代码**是这些指令的文字。你写代码，电脑照着做，再把结果显示出来。

## 先准备好工具，再学写法

先完成[第一个程序](../getting-started.md)，确认屏幕出现了你写的文字。还没拿到能用的 EL 工具时，可以先在纸上算例子的结果；这能练习读代码，但不能代替在电脑上运行。

接下来的程序只在屏幕上显示结果，不会购买东西，也不会替你修改其他文件。

## 每次只做一个小任务

| 顺序 | 要解决的问题 | 新学的工具 | 做完怎样检查 |
| --- | --- | --- | --- |
| 1 | [零花钱还剩多少](budget.md) | 变量、计算、输出 | 换一个价格，余额跟着变 |
| 2 | [钱够不够买](decisions.md) | 比较、`if`、`else` | 够、不够、刚好三种情况都对 |
| 3 | [把阅读记录加起来](lists.md) | 数组、`for`、累加 | 增加一天，合计自动变化 |
| 4 | [重复的计算只写一次](functions.md) | 函数、参数、返回值 | 同一条规则算两笔采购 |
| 5 | [完成文具采购小助手](shopping.md) | 组合前面四种工具 | 按验收表逐项核对 |

这里的“检查”由你完成。页面上的勾选框是提醒，网站不会替你运行 EL，也不会判断你是否学会。

## 怎样读，才不只是觉得眼熟

每节先看一份完整程序和结果，再自己运行。接着只改一个地方，运行前先说出你预计会看到什么。最后收起例子，做页尾的小任务；想不起来就回看相关一步。

例如，把价格从 3 元改成 4 元之前，先算一算余额应该少多少。实际结果不同，就检查改动和计算过程；“结果不一样”是线索。

不用一口气学完。下次回来，先不看答案，试着写出上次最重要的两三行，再继续。能解释“为什么这样算”，比记住整页的长相更有用。

## 遇到英文，先看它在这里做什么

代码里的英文需要按原样拼写，大小写也要一致。第一次遇到的词会在附近解释，不要求先背词表。

| 你会看见 | 在这里的意思 |
| --- | --- |
| 文件 | 电脑里保存的一份内容，例如 `budget.el` |
| 文件夹 | 用来放文件的地方 |
| 终端 | 输入命令、查看运行结果的窗口 |
| 命令 | 请电脑执行操作的一行文字，例如 `el run budget.el` |
| 输出 | 程序显示出来的结果 |

读不懂时，先分清自己卡在哪：文件没存好、命令没找到，还是程序结果不对。它们需要检查的地方不同，[第一个程序](../getting-started.md)末尾有对应办法。

## 带走这三样

- 每节做成一件小事，不要求一次记住所有英文。
- 先运行完整例子，再改一处，最后自己写。
- 用预计结果与实际结果对照，判断程序是否符合你的想法。
